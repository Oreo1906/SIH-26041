## Local setup (Windows PowerShell)

Prerequisites: Python **3.13.9**, Node **24.11.1** (npm **11.6.2**). Dependency
downloads need network access during developer setup. This is separate from the
eventual offline worker training path. No Git remote is needed to run locally.

From this repository folder:

```powershell
python -m venv backend/.venv
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
Set-Location admin-web
npm.cmd ci
Set-Location ..
python scripts/verify.py
```

The verification script runs backend tests, builds a Python wheel, runs admin
tests, and typechecks/builds the admin. It exits nonzero on failure and saves
logs to `artifacts/verification/`. It does not claim to verify Unity or an APK.

Start the backend in one terminal:

```powershell
Set-Location backend
.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Start the admin in a second terminal, from the root:

```powershell
Set-Location admin-web
npm.cmd run dev
```

Open [the admin preview](http://127.0.0.1:5173), then choose **Check connection**.
[Health](http://127.0.0.1:8000/health) returns
`{"status":"ok","version":"0.1.0"}`;
[OpenAPI documentation](http://127.0.0.1:8000/docs) is generated by FastAPI.
Stop either service with Ctrl+C. No login/worker data is served yet.

Vite proxies `/health` and `/api` to local port 8000 during development. A later
deployment must supply the equivalent same-origin reverse proxy; `vite preview`
alone only serves the built static admin and is not a production backend proxy.
`backend/.env.example` lists reserved/reference environment variables; it is not
automatically loaded. No credentials are needed for the health endpoint.

On Linux/macOS use `backend/.venv/bin/python` in place of
`backend/.venv/Scripts/python.exe`, and `npm` in place of `npm.cmd`.

Artifacts: `backend/dist/*.whl`, `admin-web/dist/`, and local verification logs.
CI is in `.github/workflows/ci.yml`; it runs when this folder is pushed to a GitHub
repository. A local passing run does not mean hosted CI has run.

## Android development preview

The editor is pinned to **6000.3.24f1 (Unity 6.3 LTS)** with Android modules. From
PowerShell, run `.\scripts\unity.ps1 -Action Test`, then `-Action Build`, then
`.\scripts\verify_apk.ps1`. Expected output is
`artifacts/android/SurakshaXR-preview.apk` (debug signed; not a release certificate).
See `STATUS.md` for actual build evidence; source code presence is not validation.
The preview bundles all content/fonts offline. ARFoundation/ARCore6.3.5 is configured
Optional with manual startup and contextual camera permission. 3D works without AR
services. Run `-Action BuildEmulator` only for the separate x86_64 development APK
under `artifacts/android/emulator-only/`; install the ARMv7+ARM64 preview APK on a
phone. Android10+ also requires compatible ARM/Neon/OpenGLES3 hardware. Never run
two Unity build processes together. UI capture: `-Action CaptureUI`; evidence in
`artifacts/ui-preview/`. [Current AR/UI notes](docs/33_ANDROID_COMPATIBILITY_LIFESIZE_AR_UI.md).
Reference layout/scale/pointer notes: [Fire and Gas layouts](docs/34_REFERENCE_SCENARIO_LAYOUTS.md).
Actual scene renders: `-Action CaptureScenes`, saved under `artifacts/scene-preview/`.

## Original product contract

This repository documentation is the source of truth for building the SIH26041 solution: an offline-first Android industrial-safety training and certification platform with two complete AR modules, an automatic 3D simulation fallback, assessment, QR certificates, Hindi and Santali localization, refresher training, and a web compliance dashboard.

## What to build

Build one Android APK for Android 10+ that works fully offline for worker training. On ARCore-supported devices, the Fire and Gas modules must offer camera-based AR. On unsupported devices, the same scenario definitions must run in a full-screen 3D simulator. The web dashboard is for compliance review and synchronization when connectivity is available; it must never be required to complete training.

## Technology baseline

- Unity 6.3 LTS for the Android worker app and 3D simulation.
- Unity AR Foundation + ARCore XR Plugin; Android AR is configured as **Optional**.
- Minimum Android version: Android 10 / API 29 for this SIH project, even though ARCore itself supports lower API levels.
- Unity Localization package for English developer strings plus Hindi and Santali production locales.
- SQLite local database inside the mobile app.
- React + TypeScript admin dashboard.
- FastAPI backend; SQLite for local development and PostgreSQL-compatible persistence for deployment.
- Signed QR certificate payloads and a preloaded offline trust bundle.

Pin exact package versions in lockfiles/manifests once the first green build is obtained. Do not upgrade dependencies during the hackathon without a concrete need.

## Non-goals for the SIH build

Do not add cloud-only AI, live translation, online authentication required for training, geospatial AR, multiplayer, wearable integration, or advanced computer vision. These can be future-work items. The winning implementation goal is reliability, offline operation, clear safety pedagogy, and complete end-to-end evidence.

## Safety-content rule

The software architecture and demo scenarios can be implemented from this specification, but operational safety thresholds, extinguisher selection rules, gas limits, PPE requirements, and emergency procedures must be treated as configurable content and validated by a qualified industrial-safety/domain expert before real-world use. The app must display a disclaimer that it reinforces approved site SOPs and does not replace them.
